# Evidence

Everything here was generated by running the code. All runs used the **offline scripted backend**, which is rule-based
code standing in for an LLM. Read the results as evidence about the harness, not about any model. See
[What was not tested](#what-was-not-tested).

## Evaluation results

Baseline `9ade7848e5dc` is 500-day equal-weighted historical VaR. All candidates used the same fixed window and the rules
in `eval/policy.yaml`, committed in `2e91b15` before any candidate ran.

| Candidate | Exceptions (2.5 expected) | Kupiec p | Independence p | Basel zone | Average VaR | Decision |
|---|---|---|---|---|---|---|
| Baseline | 10 | 0.0003 | 0.051 | Red | 3.72% | |
| `age_weighted_var` (decay 0.99) | 7 | 0.0190 | 0.174 | Yellow | 4.87% | **Reject:** average VaR +31%, limit 25% |
| `short_window_var` (125 days) | 9 | 0.0014 | 0.032 | Yellow | 4.80% | **Reject:** average VaR +29% |
| `loose_outlier_filter` (z of 50) | 10 | 0.0003 | 0.051 | Red | 3.72% | **Reject:** missed bad tick F1, and no improvement |
| `age_weighted_gentle` (decay 0.995) | 8 | 0.0054 | 0.018 | Yellow | 4.51% | **Accept** |

**The active version is still the baseline, on purpose.** Acceptance makes a candidate eligible for promotion, and
promotion is a person's decision. Three reasons to pause before making it:

- `age_weighted_gentle` was designed after seeing `age_weighted_var` fail on this same window, so its result is in-sample.
- Its independence p-value got worse (0.051 to 0.018), meaning exceptions cluster more. The pre-registered rules do not
  test this, which is a gap in the rules that this run exposed.
- `age_weighted_var` has the best coverage and independence, and failed only the VaR guardrail. Whether that guardrail
  is right is a fair question, but changing it after seeing the result would defeat the point of fixing it first.

## What was not tested

- **No real LLM has run this workflow.** No API key was available during development. The adapters were tested only
  against a local fake server that speaks both protocols, so a real vendor may differ in ways it does not. Agent quality,
  real token costs and how well prompts work are all unmeasured. `riskwatch provider-check` plus a short replay is the
  first step, and with a live model the 928-call full-year evaluation would need repeat runs, because outputs vary.
- **The scripted agents are simple rules.** Their memos read flat because they are templates. They also can't really
  respond to feedback, so revision evidence shows the loop working, not a draft improving through reasoning.
- **Approvals were simulated** by `replay-policy` in every recorded run. No real person's judgement is evidenced.
- **One window, one crisis.** Evaluation covers 253 days and about 250 VaR observations. Limit levels and the data steward's
  thresholds were set after looking at this same window, so results may not carry over to another period.
- **The injection defence has layers, not a guarantee.** The quarantine filter is a list of regular expressions, and a
  reworded attack would get past it. The remaining protection is that agents hold no tools that write, and that the
  verifier and human gate do not depend on the model.
- **Model memory is reduced, not eliminated.** Dates are hidden and known terms are blocked, but a model could still
  infer the period from the size of the moves.
- **Time limits are checked between stages and before LLM calls**, so a hung calculation is not pre-empted. In production a
  scheduler timeout should back this up.
- **A crash after a provider replies but before the journal commits repeats that one call.** The hard-kill test cannot
  see this, because a repeated call leaves no extra row.
- **Restatement materiality ignores P&L.** The 2020-04-08 correction moved the reported return by 26bp without a notice, since
  the rule looks only at VaR and limit status. All three replay corrections were immaterial, so the material path is
  covered by a test only. Adding a P&L threshold is a natural next candidate.
- **Scale.** One controller, one worker, SQLite. Fine for one book, not for many.
- **Platform.** Developed and tested only on Windows 11 with Python 3.15.
